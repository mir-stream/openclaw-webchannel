## 🟠 MAJOR — 운영 안정성 (라이브 NATS 경로 / 서버)

### S1 — NATS 재연결이 아예 없음
- **검증:** ✅ VERIFIED (transport에 reconnect 코드 없음; keepAlive는 로그만)
- **위치:** `packages/plugin/src/nats-transport.ts`(재연결 없음) + `index-nats.ts:734-745`(keepAlive)
- **시나리오:** NATS 재시작/WS drop → `close`가 `_connected=false`로 두고 `disconnect`가 subs까지
  비움 → `sendToPeer` 영구 false, keepAlive는 "awaiting reconnect…" 로그만. 아무도 `connect()`를
  다시 안 부름 → 프로세스 재시작 전까지 영구 wedge. docs의 "auto-reconnection" 주장과 배치.
- **수정 방향:** C1의 error 핸들러와 묶어 backoff 재연결 + 재구독 복원.
- **→ ✅ FIXED (2026-07-02):** `NatsTransport`에 opt-in 자동 재연결 추가(`reconnect` 옵션, 기본
  `false`로 기존 호출자/테스트 무영향). **established 연결이 끊긴 경우에만** 지수 backoff
  (`reconnectBaseMs`=500 → `reconnectCapMs`=15s, `maxReconnectAttempts`=∞)로 재다이얼하고, 성공 시
  `this.subs`의 subject를 새 sid로 **replay해 inbound 전달 복원**. 초기 `connect()`는 재시도 안 함
  (첫 연결 실패는 호출자 소관). `disconnect()`는 `closed` 플래그로 진행 중 재연결을 취소. 트리거는
  close 핸들러 1곳(per-socket `handshakeDone` 게이트)이라 초기연결 실패·실패한 재연결 시도는
  중복 스케줄 안 됨(실패한 시도는 `reconnectOnce` catch가 재스케줄). 라이브 3경로 모두 `reconnect:
  true` 배선(`nats-credential-source.ts` open/static, `enrolled-nats-connection.ts` enrolled). 타이머는
  `unref`. 재연결 유닛 테스트 3개(재연결+구독 replay / disconnect가 backoff 취소 / disabled 시
  무재연결). **잔여 edge (양성):** 재연결 후 transport sid가 바뀌어 `NatsChannel`의 per-peer
  `peerSubscriptions`/`handshakeSubscriptions`에 저장된 old sid가 stale → 이후 `unregisterPeer`의
  `unsubscribe(oldSid)`가 no-op(구독 leak). 단 NATS 경로엔 peer-disconnect 신호가 없어 unregister가
  거의 안 불림(S2) → 실무 영향 미미. 완전 해소는 S2(peer-disconnect teardown)와 함께.
