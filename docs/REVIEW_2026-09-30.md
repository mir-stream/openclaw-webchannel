# WebChannel 전수 검수 (2차) — Telegram 책임 경계 비교

검수일: 2026-09-30. 기준: `origin/develop` `732ef8b` (R1–R10 수정 PR #390–#394 병합 후).
Telegram 비교 소스: `../openclaw/extensions/telegram` @ OpenClaw `54257e02001`.
원칙: **“우리 플러그인 = Telegram 서버 + Telegram 플러그인, 우리 클라이언트 = Telegram 앱.”**

1차 검수(2026-09-23, R1–R10은 PR #390–#394로 수정·병합)의 R/G 항목과 열린 이슈 124건은 재발견 대상에서 제외했다.
R 수정이 불완전한 경우만 “R# 불완전”으로 표시했다.

## 결론

**선을 긋는 방식은 원칙에 맞다.** 플러그인이 seq와 서버 ID를 발급하는 유일한 권위이며,
수락 트랜잭션도 플러그인이 잡는다. user row와 dispatch row를 한 SQLite 트랜잭션에 쓴 뒤 ACK한다.
재시작 복구, 등록 인증(JWT + PoP + wrap), 계정별 lease도 서버 쪽에 있다.
클라이언트는 local echo, random_id 재전송, 서버 ID 채택만 맡는다. text/position 추측 채택은 제거됐다.
R9·R10 수정은 완결됐고, R5 tenant 격리에서도 구멍을 찾지 못했다.

**남은 문제는 세 가지 성격이다.**

1. **Telegram 플러그인이 쓰는 SDK 표면의 누락.**
   `messaging` adapter와 `resolveOutboundSessionRoute`가 없다. empty-reply fallback은 당시 누락으로
   판정했고([C3 정정](#2026-10-01-정정--c3)), typing keepalive, 명령 권한 부여, config schema의
   `defaultAccount`도 없다.
   그 결과 코어가 먼저 보내는 발신(message 도구, CLI, cron)이 실패하거나 엉뚱한 세션에 기록된다.
2. **서버가 확정해야 할 사실을 클라이언트나 우연이 대신 확정하는 경계.**
   - turn 진행 여부: 30초간 조용하면 클라이언트가 자체 복구에 들어가 진행 표시를 지운다.
   - 승인 결과: 클라이언트의 추측이 확정 표시로 바뀐다.
   - Retry 멱등성: 같은 요청을 여러 번 다시 실행할 수 있다.
   - 두 번째 `/stop`: 나중 turn을 취소한다.
3. **서버 수명·저장의 blast radius.**
   - 계정 하나의 고장이 모든 계정의 수신을 소리 없이 막는다.
   - 저장소가 issuer에 묶이지 않는다.
   - journal에 epoch가 없다.

### 2026-10-01 정정 — C3

#404의 [오너 정정 1](https://github.com/mir-stream/openclaw-webchannel/issues/404#issuecomment-5924069816)과
[오너 정정 2](https://github.com/mir-stream/openclaw-webchannel/issues/404#issuecomment-5926887447)에 따라
C3의 SDK 해석을 바로잡는다. pinned SDK `2026.7.1-2`에서도 interactive 응답이 실제로 완전히 비면
코어가 `isError` 페이로드를 만든다. 반면 `noVisibleReplyFallbackEligible`은 queued/follow-up,
message-tool 전달, continuation, 의도적 silence를 구분하기에는 거칠다. 이 신호만으로 빈 응답을
판정하면 정상 작업의 재시도를 유도할 수 있다. TD-3의 목표 결정은 유지하되 구현은 SDK 업그레이드
때까지 보류한다.

## 검증 한계

- 로컬 설치 SDK는 `2026.6.10`이고, pin은 `2026.7.1-2`다. D 검수자는 pin 버전을 `npm pack`해 일부 경로를 직접 확인했다.
- 전체 suite, 실제 gateway·브라우저 E2E는 돌리지 않았다. probe는 작은 스크립트와 단일 vitest 파일이며 `lockf`로 직렬화했다.
- G-1의 "코어 plugin-service 시작 보류"는 STATUS.md가 **의도한 전역 fail-closed 안전 장벽**으로 명시한다. 결함으로 본 것은 두 가지다. 건강한 계정까지 함께 막는 범위, 그리고 막혀 있는 동안 ACK도 reject도 없이 메시지가 사라지는 침묵이다. 차단 범위와 복구 안전성의 trade-off는 [#426](https://github.com/mir-stream/openclaw-webchannel/issues/426)에서 별도로 결정한다.
- 파트별 상세 보고서와 probe는 세션 임시 공간에 있었고 보존되지 않았다. 재현 근거는 각 이슈 본문에 남겼다.
